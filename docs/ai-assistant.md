# AI 助手机制与使用

AI 助手沿用项目原有的生成、完善和排错功能，增加流式预览、结果检查、局部编辑、有限次数自动纠错、草稿保护以及本地历史恢复。适用于网页和桌面打包使用的同一套前端。

## 日常使用

1. 在 AI 面板的模型配置中填写兼容接口、模型和自己的密钥。
2. 输入需求，点击「开始生成 / 修改」。默认自动逐步显示返回内容；完整回复检查失败时，最多额外请求模型修正两次。
3. 查看检查结果与修改前后对比，再自行选择载入或推演。生成和纠错期间不覆盖编辑器。
4. 只想改局部时，选择「只改选定步骤」，勾选一个或多个步骤。程序合并这些步骤，并保留其他步骤、全局信息和注释；增删步骤应使用整份脚本模式。
5. 「历史与版本」可以搜索任务、选择原稿或生成版本、比较后恢复、手动保存草稿及导出历史。恢复前会备份当前内容，工具栏「撤销 AI 载入」可撤销最近一次载入或恢复。

主界面说明当前自动处理方式；流式开关、自动纠错和次数限制放在默认折叠的「高级设置」。接口不支持流式时可以关闭。自动纠错可能增加等待时间和模型调用费用。

## 完整性和草稿保护

- 默认总超时为90秒，可在模型设置中调整为5—300秒；生成和额外纠错共享同一时间预算，可随时中止。
- 区分正常结束、长度截断、内容过滤及缺少结束标记。未完整结束或检查失败的 AI 结果只允许查看与复制，不能载入或推演。
- 检查脚本解析、原子和元素、键引用与键级、有限坐标，以及多步骤的原子编号、元素计数和总电荷。检查通过仍需专业审核化学机理、价态与立体化学。
- 流式接收期间只更新预览文字；完整结束后才合并、检查和计算差异。向上阅读可暂停跟随，异常中断保留收到的片段。
- 写入前重新检查目标与草稿。等待期间或备份保存期间的手工修改、切换机理或账号都会阻止过时结果覆盖；备份写入失败时也不覆盖。
- 取消后的旧响应不会影响新任务。自动纠错仅处理完整回复的本地检查错误；截断、网络错误、认证错误和重复失败不会无限重试。

## 本地历史的范围

历史按当前本地账号区分，访客单独保存；优先使用 IndexedDB，缺少时使用 LocalStorage。IndexedDB 每账号最多100条、约1200万序列化字符；备用存储最多30条、约120万字符，达到限制会清理较旧记录并提示，可导出另存。

历史只保存在当前浏览器和站点地址下，不会自动同步到 Upstash 或其他设备。清除站点数据会清除历史；导出目前不提供对应的导入按钮。过去未保存的生成无法重建，刷新或关闭尚在进行的任务也不能保证保存未归档片段。

历史不复制配置中的 API Key、接口地址或请求头；用户输入的需求和脚本会保存，浏览器本地内容没有额外加密。生成前原稿和手动快照可以恢复为未完成的草稿；失败或截断的 AI 输出不能通过历史绕过检查。

## 验证

```sh
npm test
npm run test:ai
npm run test:server
npm run build
```

AI 专项测试覆盖流式断包、截断、总超时、纠错次数、局部合并、草稿冲突、撤销、历史存储及安全显示。测试采用模拟模型回复，不调用付费模型；实际模型生成质量、耗时和不同接口的兼容情况需要单独实测。

`npm run build` 沿用现有桌面前端打包流程，新 AI 模块随 `js/` 一起进入 `dist/`。云端 API 地址、Upstash 适配、服务端数据库及 Tauri 窗口配置由项目原有实现负责。
