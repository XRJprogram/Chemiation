# AI 对话细节优化（2026-10-25）

沿用原项目、原两区布局、原 AI 对话标签、原 IndexedDB 与 Upstash 会话存储。本轮没有更换界面框架、数据库或动画引擎；此前的本地修改完整保留，未推送或部署。

## 四项修改

1. **保留指定步骤范围**：选择“完善本步”即保存所属机理、步骤编号、步骤名称、原稿和用于修改的脚本。刷新、切换到另一段对话后再返回，仍锁定原来的步骤，并定位到该步骤。后续追问及重试沿用范围。脚本内容真正变化时保留范围提示并阻止发送，要求重新选择；取消范围需主动点击标签旁的 ×。
   原项目刷新会重新序列化脚本；仅注释和引号外空白改变，且没有未保留候选改稿时，允许重绑定到当前文本。其他步骤始终使用当前原文，不根据相似机理推断可覆盖。
2. **提问表单保存草稿**：单选项与未提交的自由回答随所属问题保存，刷新和切换聊天后恢复，提交按钮按恢复内容启用。历史已回答的表单继续锁定。草稿保存在本机后再排队同步云端，快速连续编辑合并云端写入。
3. **在对话内处理失败**：失败消息直接展示原因，并可展开收到的脚本片段；截断、超时、校验失败、手动停止或缺少模型配置均可保留原请求重试。点击按钮才开始新一轮，仍沿用原提示、原上下文位置、原脚本和原步骤范围，不重复添加用户消息。保留原来的有界纠错、共享超时预算和原稿保护。收到的失败片段不能直接用于动画或应用。
4. **完善对话管理**：在原“历史”面板添加按对话名称搜索、行内改名、删除及二次确认，支持当前对话和同项目其他对话。删除聊天及其草稿、版本，不删除当前机理脚本。删除当前对话后进入一段新对话。登录状态先等待已有同步完成、删除云端，再删除本机；云端失败保留本机记录。旧窗口的过期保存会被现有版本校验拒绝，避免复活已删除的对话。

## 存储兼容与上线

- 会话新增可选 `scope: {projectId,index,stepName,baseScript,script}`。
- 问题消息新增可选 `answerDraft: {selected,text}`，只保留题目已有的选项，文字最多 2000 字符。
- 失败消息新增可选 `retry: {prompt,refining,sourceScript,baseScript,projectId,scope,userMessageId}` 与 `failure: {status,detail,fragment}`。所有字段继续受原文档容量限制，不保存模型密钥或连接配置。
- 原有会话缺少这些字段时仍可读取，不需要手动建表或迁移，不新增 Redis 键和 API。
- **需同时更新前端及服务端依赖的 `js/aiStudioCore.js`**。原 `server.bat` / `npm start` 启动方式不变；只更新网页不能让旧服务端保留新增字段。客户端会检查服务端返回的消息和范围，丢字段时提示更新，不显示完整同步成功。
- 对话名称搜索只查当前机理项目的标题，不表示已实现所有聊天正文的云端全文搜索。

## 验证方式

自动测试使用临时账号和临时数据目录；模型输出由本地模拟接口提供，不调用付费模型，不连接生产 Upstash。

- AI 单元与集成回归：`npm run test:ai`。
- 原服务端回归及会话存储、账号隔离、版本冲突、Upstash REST 合约：`npm run test:server`。
- 真实 Chrome：`npm run test:studio:browser`。覆盖刷新/切换后的步骤锁定、表单草稿恢复、指定步骤失败后重试、真实内容变化拦截、标题搜索、当前/其他对话改名、取消删除、云端删除失败保留、两端删除和过期写入拒绝；继续覆盖原流式预览、自动纠错与手机布局。
- 原静态构建：`npm run build`。

真实模型生成质量、实际 Upstash 权限与生产网络情况仍需部署后验收；本轮未使用团队密钥或修改生产数据。

实际结果：原包校验通过，AI 回归 **158 项通过**；原服务端集成 **23 项通过**，会话存储 **15 项通过**；真实 Chrome **34 个场景通过**，模拟模型请求共 22 次；静态构建与差异空白检查通过。模型与 Upstash REST 合约均使用模拟环境，不代表生产实例已验收。
