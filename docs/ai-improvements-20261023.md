# AI 模块检查与本轮改进

日期：2026 年 10 月 23 日。

结合新的参赛材料，本轮优先检查 AI 从需求、脚本到动画的可靠性，在现有项目和现有校验、聊天、检索流程上补强。保留原有界面、动画引擎、数据库结构和有限自动修复策略，没有引入额外框架或模型调用。

## 已复现并修复的问题

### 一 能解析且守恒的脚本仍可能存在明显价键错误

修改前：单个碳连接五个氢、每条为单键的脚本，可通过现有检查。语法、原子引用、元素计数正确，并不能排除这样的错误。

修改后：在现有 `aiTaskSafety.js` 中增加常见普通共价结构的键级总和上限检查，覆盖 H、C、N、O、F，以及氮和氧的常见带电形式。错误诊断包含步骤编号、原子编号、元素、电荷和键级总和，交由原有自动修复流程处理。CCPL、JSON、流式完整步骤、最终结果和恢复版本使用同一校验入口。

该检查只排除明显不合规则的普通结构，不强制补齐氢、键或形式电荷，不因原子成键偏少就自动判错。稠合芳香碳有专门的编码容差；芳香杂原子、金属配位、桥氢及未覆盖的特殊价态保留专业审核提示，不按普通分子规则机械拦截。候选预览区域会显示检查提示，提醒哪些情况仍需审核。

常见元素价态与电荷处理参考 [RDKit 官方说明](https://rdkit.org/docs/RDKit_Book.html#valence-calculation-and-allowed-valences)。本项目没有引入 RDKit，也没有实现完整的化学感知、芳香性识别或量化计算。通过检查仍不等于机理、立体化学或反应条件正确。

### 二 长对话会遗失最早的需求

修改前：只将最近 14 条消息发给模型。经过多轮修改后，最初指定的底物、溶剂或限制可能不再出现在请求里。

修改后：在现有 `aiStudioCore.js` 中增加有容量上限的上下文选择，优先保留原始用户需求、最近对话以及较早已回答的问题与条件；用消息编号保持问答关系，按原时间顺序发给模型。使用用户原话，不由另一个模型生成可能失真的条件摘要。

历史上下文最多 20,000 字符、32 条消息，不包含系统提示和本轮脚本。消息整条选择，不静默截断条件；容量不足时在模型请求中明确说明省略了历史，要求关键信息不足时追问。最新明确修改优先于旧要求。极端长记录无法全部保留，不能承诺无限记忆。

各个对话仍然隔离，不会为补充上下文自动读取同项目下其他对话的正文，也没有新增数据库字段。

### 三 检索的停止与超时未覆盖本地历史等待

修改前：远程请求有超时，但本地历史查询卡住时仍可能阻塞整个检索；在等待期间切换账号或项目，也可能让后续请求使用变化后的身份。

修改后：本地历史查询、命中脚本读取、远程检索与响应读取共用约 1.6 秒等待预算；历史或远程慢时优先返回已经可用的本机结果。点击停止立即结束界面等待，过期返回值不会触发后续生成。

每轮检索固定捕获开始时的账号、令牌、项目轮次、对话和任务轮次，异步返回后重新检查。切换项目或账号时取消旧检索；不会用新账号身份发送旧对话的提示词。

这个预算约束异步等待，不能中断 JavaScript 已在执行的同步解析和布局，因此不应将它宣传为整个生成过程在 1.6 秒内完成。

## 本轮验证

- AI 自动测试 155 项通过，比此前增加 10 项，覆盖价键错误、常见离子、特殊结构边界、自动纠错、长对话、上下文容量和异步检索隔离。
- 原有服务端 23 项场景与新增对话存储 14 项测试通过。
- Chrome 浏览器 29 项场景通过，比此前增加 3 项：长对话条件保留、五键碳自动修复、本地历史等待期间停止。原有流式预览、指定步骤修改、版本恢复、账号隔离和 320 像素窄屏场景继续通过。
- 原有基础包验证、资源构建和差异格式检查通过。

测试使用本地模拟模型、临时账号和临时数据目录。没有调用收费模型或写入生产 Upstash，也没有以这些工程回归测试推算材料中的化学准确率。

## 仍需继续完善的能力

| 方向 | 目前的不足 | 后续处理方式 |
| --- | --- | --- |
| 机理检索 | 名称和关键词相近，仍不能证明底物结构、溶剂和条件适用 | 先为机理资产补充明确的条件与来源，再评估结构检索；涉及数据库结构扩展时先说明范围 |
| 专业正确性 | 基础规则不能验证路径、立体选择性、过渡态和能垒 | 建立有来源、有专业审核结果的固定样例集，分别衡量格式、基础规则与专业正确性 |
| 真实模型评测 | 自动测试以模拟响应验证流程，不代表服务商的实际生成表现 | 使用团队授权的测试模型与预算记录成功率、耗时、失败类型和修复次数 |
| 规划与生成分工 | 当前是现有生成与校验修复流程，不能直接认定已完成材料中的独立双智能体 | 真正拆出规划数据、编译输入和调度会改变执行流程，单独设计后再实施 |
| 生产同步 | 本地与模拟接口回归通过，真实部署权限、配额和同步仍需验收 | 在队长的测试环境验证现有存储 PR，不自行改动生产数据库 |

本轮没有进行这些架构扩展，也没有新增或推送 GitHub PR；上一轮存储 PR 保持独立。新增改动已写入本地完整体验版，可通过原有 `server.bat` 启动。
