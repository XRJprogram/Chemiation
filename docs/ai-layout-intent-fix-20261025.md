# “布局清晰”被误判为“只改布局”的修复

## 现象和复现

失败消息提示“本轮只允许调整坐标布局，检测到化学结构或其他受保护内容变化”，同时保留了模型已返回的完整脚本。直接原因是任务的 `workflow.policy` 为 `layout`，而返回内容超出了坐标范围；这条报错本身不是 API 认证或网络错误。

在已有候选或指定步骤的场景下，可确定复现一处程序误判：`请生成苯的硝化完整脚本。本次只展示核心取代过程。苯环布局清晰。` 被记录为只调整布局。更小的复现是：`请完善当前机理；本次只展示核心过程，苯环布局清晰。`

旧识别规则分别搜索整段文本中的“布局”和“只/仅”，没有要求限定词真正修饰布局操作，所以两句无关要求会组合成限制。无法直接读取用户当时的浏览器任务状态，因此不推断其是否另行选过布局选项或保留了旧任务。

## 修改与边界

只在限定词直接约束布局、坐标、排版或位置时建立布局限制；同时保留“保持结构不变，调整布局”等明确保护结构的请求。原稿保护、步骤范围检查、格式检查和基础化学结构检查继续执行。

新增两个回归测试，先验证失败，再验证修复通过：一个覆盖已有候选和指定步骤下的误判，一个实际经过 AI 请求和校验流程，确认合规完整回复不会仅因此追加纠错请求。明确的布局修改仍阻止更改结构和说明。

旧失败记录保留原请求及其限制，不自动扩大修改范围。更新后宜新建对话重发完整需求；旧记录的“重试”会继续使用保存的任务快照。体验页刷新后需重新选择“使用真实模型”，演示模式和真实接口配置保持原有切换方式。
