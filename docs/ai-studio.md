# 对话式机理工作台

这次改动在原项目中增加右侧聊天工作区，继续使用现有 Canvas 动画、CCPL 编辑器、AI 请求与校验流程、登录账号和 Upstash Redis 接入。不需要换数据库或引入前端框架。旧生成器保留在“设置”弹窗中，其历史记录保持独立。

AI 界面复用原项目 `chemiation.css` 的主题变量：宣纸背景、深棕文字、赭红主按钮和选中态；标题、正文、输入框与菜单统一使用原项目的 `--font-sans`，脚本内容使用原有 `--font-mono`。问题卡、消息、历史和预览状态沿用同一套底色、边框、阴影与按钮圆角，紧凑布局和原有交互保持不变。

## 体验流程

1. 启动项目原有的 `server.bat`。原工作区顶部的模块顺序为“机理步骤｜CCPL 脚本｜AI 对话”，AI 入口位于 CCPL 脚本标签右侧；点击后在同一内容区切换，未新增独立侧栏。
   点击 AI 对话顶部“项目名 / 对话名 ⌄”展开项目与对话选择，点击右侧“＋”新建对话。每个机理可以有多段对话，每段保存自己的消息、追问、输入草稿与脚本版本。切换机理会停止旧生成、撤回旧预览并载入该机理上次使用的聊天；刷新恢复当前账号上次选中的机理项目和对话。
   当前对话可在下拉面板内点击“重命名当前对话”，或打开“历史与设置 → 重命名当前对话”。输入名称后保存，取消和 Escape 不会修改名称；聊天、未发送草稿、候选版本与机理脚本保持保留。修改其他对话的名称继续在历史列表操作。
2. 点击“从已有机理开始”，无需配置模型即可检索、预览现有酯化示例。预览支持底部步骤切换与播放，原脚本暂时不变。
3. 点标签行右侧“历史与设置 → 模型设置”配置原有 AI 服务商、端点、模型和 API Key，然后输入反应需求。信息不足时显示问题卡片，包含问题、单选选项、自由回答和“提交并继续”；可以单选、只输入文字或同时补充。回答带上原问题发给模型，并锁定已回答的旧表单，避免重复发送。表单跟随聊天保存，刷新后可继续；旧格式追问也支持自由回答，不会凭空补造化学选项。
4. 对话默认请求流式输出，可展开“查看正在生成的脚本”。每出现新的完整 step 块或完整 JSON 步骤对象，先做基础检查，再在左侧临时预览；只完善当前步骤时，先合并原稿并检查整份机理，其余步骤不变。解析更新节流到约 160 毫秒，不逐字执行半截结构。画布和聊天均标出生成、纠错与预览状态。后续步骤无效、超时、截断、停止或草稿冲突时撤回临时预览；每次自动纠错清空上一轮的临时结果。只有完整回复通过检查后才形成可保留的候选版本。检查失败默认最多追加两次修复请求，共享原有任务超时预算。
5. 点击“完善本步”，再描述修改要求；发送时锁定当前步骤，只接收该步骤补丁，其余内容逐字保留。追问、刷新和切换回本对话仍保留这个范围。若步骤说明或结构已变，提示重新选择，不自动扩大到整份脚本。刷新造成的纯注释或空白整理，在没有未保留候选改稿时可保守重绑定，并以当前文本为基准保留其他步骤。
6. “对比原稿”切回原动画，“查看新版本”切回候选。“保留此版本”才写入编辑器与机理；写入前必须成功保存本地记录和原稿备份，并再次检查目标、原稿、结构与范围。
7. 打开“历史与设置 → 聊天与脚本版本”，只列当前机理项目的聊天及当前对话的脚本版本，可按对话名称搜索、在原列表中改名或确认删除，也可导出当前会话的完整 JSON。删除对话包含其聊天、草稿与版本；当前机理脚本继续保留。登录用户先删除云端，再删除本机；云端删除失败时保留本机记录。恢复会留下新的恢复记录，恢复前的脚本仍可找回。旧版没有项目归属的聊天单独保留，可明确点击“复制到本项目”；复制产生新的会话，原始旧记录保持不变。
8. 截断、停止、超时、认证或校验失败的消息下方可查看失败原因与已收到片段，点击“重试这次生成”会使用原请求、原上下文位置和原修改范围，不重复添加用户消息。原稿已变化时阻止旧请求重试；需重新选择并发送要求。模型配置仍从当前设置读取，失败记录不保存密钥。

访客数据保存在浏览器；登录后新建的对话还会同步至现有服务器。访客聊天不会自动转移给登录账号。换账号、退出、手动改稿或切换反应时，过期任务和预览不会覆盖当前工作。

### API 连接测试

“测试连接”使用设置面板中当前填写的服务商、接口地址、密钥和模型，不再误用旧的已保存配置。测试不会自动覆盖已保存的密钥；成功后点击“保存配置”，再开始生成。空密钥或粘贴了 `Bearer` 前缀、外围引号时先给出明确提示，不发送请求。HTTP 401 会明确标为模型服务拒绝当前输入的密钥；这不等于本地网站无法连接 API，也不能仅凭这次界面修复确认真实密钥有效。

## 界面

沿用项目的米白与棕色和原有两区布局：左侧反应动画，右侧推演工作区。在原有“机理步骤”和“CCPL 脚本”之后追加“AI 对话”模块，三者在同一区域切换，未增加独立侧栏。切换保留会话与编辑内容，脚本全屏编辑仍可使用；手机继续采用上方画布、下方工作区。播放控制仍在原工作区底部，所有模块都能操作。收起、展开保持当前选中的模块。新增样式集中在 `css/ai-studio.css`。

2026-10-21 的交互优化加强了选项选中态、键盘焦点、来源预览按钮、版本操作、停止与发送按钮的层次。问答卡片在聊天滚动区域内；追问时优先显示表单，普通输入框暂时收起，可点击“直接发消息”展开，避免重复输入区挤占画面。填写回答时跟随卡片底部，保持提交入口可见，指定步骤标签和播放控制始终独立保留。实时预览复用原动画引擎，不新增第三列、不更换数据库或前端框架。

## 保存与同步

- 数据关系为“账号 → 机理项目 → 多段对话 → 消息与脚本版本”。会话新增 `projectId`、`projectName`、`draft`；项目用原机理的固定 `id` 关联，改名不会建立新项目，也不按名称或列表下标绑定。缺少有效编号的机理在当前原有机理对象中补上持久编号。新对话只使用自己的消息作为模型对话上下文；已有机理检索仍可显式引用当前账号其他对话中保留的脚本，不会自动拼接那些聊天正文。
- 本机：独立 IndexedDB `chemiation-conversations-v1`，按账号与会话编号存储、按项目筛选元数据；每个账号/项目分别记录最近会话。输入框草稿在停顿约 500 毫秒及切换前保存；问题卡片的选项与自由回答修改后立即入本机保存队列，快速连续编辑合并云端写入。原来的 `chemiation-ai-history-v1` 不迁移、不删除。
- 服务端：新增 `server/studioStore.js`。未配置 Upstash 时，在原 `CHEMIATION_DATA_DIR` 下的 `studio/<userId>/<sessionId>.json` 原子保存，适用于单 Node 进程部署。
- Upstash：复用原有 `UPSTASH_REDIS_REST_URL`、`UPSTASH_REDIS_REST_TOKEN`、`UPSTASH_REDIS_PREFIX`。新增每账号的会话 hash 与排序索引，按会话加载、按页列出；不把聊天加入原有启动时全量加载的数据快照。
- 云端写入通过 Redis Lua 比较版本号后原子写入；JSON 字符串直接保存，避免 Lua 将空数组改成对象。版本号不匹配返回 409，不覆盖较新的会话。
- 云端项目过滤仅读取元数据（每账号最多 100 条会话），不全量下载正文。已有会话不可直接更换项目；本机存储及云端 Lua 写入均检查项目关联，改归属需复制为新对话。
- 本地也检查更新序号。云端未确认时只显示“本机已保存”；失败后可在历史中重试。存在云端冲突时，可先导出，再打开云端；打开不同内容的云端记录前，自动另存本地副本。
- 每次保存有明确边界：每会话最多 160 条消息、40 个脚本版本、240 万序列化字符；每脚本最多 20 万字符；服务端每账号最多 100 个会话。达到限制时停止覆盖并提示导出、新建；不会静默删除旧版本。可从历史中主动确认删除旧对话。
- 存储通过白名单归一化，不包含模型配置和 API Key。用户主动输入在聊天文本中的内容仍会作为聊天保存。
- 消息新增可选 `question: {question, options: [{label, value, description}]}` 和 `replyTo`，每题最多四个选项并限制字段长度。旧会话继续兼容；使用相同 IndexedDB 和 Upstash 会话记录，无需手工建表。云端需同时部署新版共享核心与后端，旧版归一化器会忽略新字段。
- 2026-10-25 增加会话 `scope`、问题消息 `answerDraft`、失败消息 `retry` 与 `failure`。这些字段沿用原会话 JSON，不新增 Redis 键或接口。失败片段仅用于查看，不直接播放或应用。云端返回时检查消息和范围是否完整保留，避免旧服务端丢字段后误显示同步成功。

### API

| 接口 | 行为 |
|---|---|
| `GET /api/studio/matches?q=...` | 检索公开机理、当前账号自己的私有机理及其历史对话中已保留的版本 |
| `GET /api/studio/sessions?offset=0&limit=20` | 登录账号的会话元数据分页 |
| `GET /api/studio/sessions?projectId=esterification&offset=0&limit=20` | 只列该机理项目的会话；`projectId=` 列未归属的旧记录；不传参数保留账号全列表的兼容行为 |
| `GET /api/studio/sessions/:id` | 登录账号的一条完整会话 |
| `PUT /api/studio/sessions/:id` | 请求体 `{session, expectedRevision}`；版本冲突返回 409 |
| `DELETE /api/studio/sessions/:id` | 从历史确认后，删除登录账号自己的指定会话 |

会话所属账号由现有认证令牌确定，不接受请求体指定账号。Upstash 凭据仍只在服务端使用。

项目关联沿用现有数据库和会话结构，无需另建数据库或手工建表。升级时需同步部署新的 `server/` 与共享 `js/aiStudioCore.js`、`js/aiWorkflow.js`；旧云端丢弃项目字段时，客户端不会显示同步成功。自定义机理跨设备使用同一组聊天，需要同时同步机理本身及其固定编号，不能仅凭同名推断为同一项目。机理脚本是项目共享的工作成果；切换聊天只切上下文，不自动替换脚本，需主动预览并保留历史版本。

## 机理匹配与正确性边界

本轮匹配本机机理库、现有云端仓库，以及当前账号历史对话中已经保留或恢复的脚本版本。先检索只含名称、编号的元数据，再加载命中的脚本，避免每次搜索读取所有聊天正文。采用名称与关键词排序，展示来源，点击后重新做基础结构检查。名称吻合和 `reviewStatus: reviewed` 标记都不触发自动采用，仍由用户核对条件后选择预览或重新推演。现有条目不会因为“存过”或“名称相同”就被自动标记为审核通过。

尚未接入外部机理数据库、分子指纹、向量索引或条件一致性证明。名称相同仍可能对应不同底物、溶剂与路径。基础检查包括语法、元素、原子编号、引用、键级、重复键、有限坐标、跨步骤元素和电荷守恒；不证明能垒、立体化学或完整反应机理正确。原项目部分教学示例不满足严格守恒，新入口会拦截它们的直接预览。

追问能力依赖模型遵循对话提示，程序识别完整的 `{"type":"question","question":"...","options":[...]}` 回复并进入下一轮；模型可能仍错误判断信息是否充分，需要用真实模型持续评估。实时动画只使用闭合且通过基础检查的步骤前缀；预览前缀不代表全部路径有效，不生成正式版本、不写入原稿。完整响应仍须检查完成标记、跨步骤守恒与指定范围。模型计算与网络延迟仍然存在，接口不支持流式时只能在整份响应到达后预览。
